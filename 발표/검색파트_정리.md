# 검색(Retrieval) 파트 — 핵심만 정리 · 팀 8

---

## ① 개선 목표와 접근 방향

**목표를 코드가 아니라 채점 결과 분해로 정했다.**

| 배점 | 축 | 점수 | 손실 |
|---|---|---:|---:|
| 20 | 검색 MRR | **20.00 / 20** | 0 |
| 30 | 키팩트 F1 | 19.65 / 30 | −10.35 (89%) |
| 50 | LLM 판정 | 48.73 / 50 | −1.27 |

→ 검색은 이미 만점. **목표는 "더 올리기"가 아니라 "이 만점이 과적합이 아님을 증명하고, 생성 파트를 고치는 동안 회귀 없이 지키는 것"** 으로 잡았다.

**접근 1 — 카카오 약관 데이터 분석부터 했다.**

| 특성 | 설계 결정 |
|---|---|
| 조(條) 단위 72개뿐 | 벡터DB 불필요, BM25로 충분 |
| 조 길이 85~3482자(40배 차) | 길이 편향 대책 필수 |
| 보일러플레이트 4개 문서 중복(유사도 0.80) | 문서명이 검색의 핵심 신호 |
| "2시간", "8세 이하" 등 정확 일치가 정답 | 임베딩보다 어휘검색이 유리 |
| 한국어 조사 부착 | 문자 2-gram 토크나이즈 |

**접근 2 — 공개 10문항을 넘어 평가셋을 직접 만들었다.**
10문항만으론 과적합 여부가 안 보여서 → 패러프레이즈 +4, 자체 함정 문항 T01~T10 +10(원문에서 예외조항·문서 간 충돌 직접 찾아 제작), 72개 조항 전수(문서명 힌트 없는 최악조건), 합성 397문항까지 확장했다.

## ② 핵심 기술과 선택 이유

```
BM25(문자 bigram)  ──▶  조전체+항 RRF결합  ──▶  리랭커  ──▶  리랭커 2채널 RRF
   기본안                    발전①                발전②           발전③(최종)
```

| 단계 | 선택 | 이유 |
|---|---|---|
| **기본안** | 임베딩 없이 **BM25 단독** | 72개뿐인 규모 + 정확 일치 도메인. 실측: dense 단독 0.90/0.80 vs BM25 1.00/0.95, 섞으면 오히려 악화 |
| **발전①** | 어절 → **문자 bigram** | 조사 변형에 강건 |
| **발전②** | 조 전체 + 항 최고점을 **RRF로 결합** | 긴 조항이 짧은 조항을 압도(길이편향) ↔ 항 단독은 반대로 짧은 항이 과대평가. **실패 방향이 정반대라 섞으면 서로 메움** |
| **발전③** | 리랭커 도입 + **조전체·서브청크 2채널 RRF** | 다른 팀 구현과 비교하니 점수는 동점(0.9750)인데 실패 문항이 정반대. 결합해서 **1.0000** 완성 |

**핵심 아이디어 한 줄**: "실패 방향이 정반대인 두 채널을 순위로 섞는다" — BM25에서 한 번, 리랭커에서 한 번 재사용했다.

**보조 장치**: 질문에 문서명이 있으면 그 문서로 후보 하드 필터링(보일러플레이트 대응) / 반환 개수는 절대 점수차 컷오프로 동적 결정(1~4개).

## ③ 주요 실험과 비교 결과

**실험 1 — 토크나이저**: 공개 10문항만 보면 어절도 bigram도 둘 다 1.000, 차이가 안 보임. **함정 10문항을 넣자** 어절 0.6417 vs bigram **0.9000**으로 격차가 드러남 → 평가셋 확장이 실제로 값을 한 사례.

**실험 2 — BM25 스코어링 방식 (핵심)**

| 방식 | 종합 20문항 MRR |
|---|---:|
| 조 전체만 | 0.9500 |
| 항 최고점만 | 0.9250 (더 나쁨) |
| **RRF 결합** | **0.9750** |

→ 둘 다 단독으론 부족한데 결합하면 개선. 실패 문항이 서로 겹치지 않기 때문.

**실험 3 — 리랭커 2채널 RRF**: 조전체 단독 0.9750(T01 실패) = 서브청크 단독 0.9750(T03 실패), 점수는 같은데 실패 지점이 정반대 → **결합하니 20문항 전부 1위, MRR 1.0000.**

**실험 4 — 검색 회수를 늘려봤다 (되돌림)**: "더 가져오면 생성이 더 담을 것"이라는 가설로 min_k=2 시도 → 회수는 늘었지만 **답변 10개 중 9개가 글자까지 동일**, 유일하게 바뀐 문항은 오히려 악화. 원인: 누락된 정답 내용이 이미 1위 조항 안에 다 있었음 → **검색 문제가 아니라 생성 문제로 확정**, 되돌리고 자원을 생성 파트로 이동.

**최종 검증**

| 검증 | 결과 |
|---|---|
| 공식 채점 (공개 10문항) | **MRR 1.000** |
| 72개 조항 전수 (문서명 힌트 없음) | 62/72(86.1%) 적중, 실패 10건 전부 확인 → **새 실패유형 0건** |
| held-out 60개 조항 일반화 | 90.0% vs 전체 90.3% — **격차 없음(과적합 아님)** |

**남은 한계**: 4개 문서의 제3조가 전부 "약관 외 준칙"(유사도 0.80) — 문서 단서가 전혀 없으면 원리적으로 구분 불가능. 실제 질문은 대부분 단서를 포함해 낮은 위험으로 판단.
