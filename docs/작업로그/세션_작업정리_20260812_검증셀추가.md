## 2. 분석으로 확정한 결론

### 2-1. 검색 k / recall (셀 3, 리랭커 경로 실측)
- 리랭커 경로는 문항당 **1개(k=1)** 반환. (오프라인 BM25 폴백은 컷오프가 죽어 항상 4개 고정 — 별개 현상)
- **recall 9/10, 완전일치 9/10.** P02(정답 3조항)만 1개 반환해 2개 MISS.
- **P02 MISS는 무해**: 세 조항(계정8·통합서비스7·통합13)은 "2시간 이상 공지"라는 **동일 내용의 중복**이고, 검색 점수 기준이 MRR(첫 정답 순위)이면 1위가 정답이라 만점. → 검색 점수는 사실상 10/10.
- 근거: 러너 코드 주석 "MRR 평가용 retrieved는 검색 결과를 그대로 보존한다"(셀0), 공개 검사기는 형식(1~4개)만 검증.
- (참고: 같은 날 다른 흐름의 컷오프 분석은 "채점이 MRR이 아니라 LLM 평가"라는 PDF 근거를 들었다. 어느 쪽이든 **P02를 무리해서 쫓을 이유가 약하다**는 결론은 동일 — 답변에 수치가 들어가는지가 관건.)

### 2-2. 과적합 여부
- **검색은 과적합 아님(근거 강함)**:
  - 코드에 문항 ID·정답 하드코딩 0건(모두 주석).
  - 평가셋에 없는 **held-out 60개 조항**으로 일반화 테스트 → top-1 **90.0%**(held-out) ≈ **90.3%**(전체). 격차 없음 = 평가셋 편애 없음. 실패 7건은 전부 4개 문서 근접중복(보일러플레이트) 한 패턴.
  - 저자가 few-shot을 "일반화 깨짐"으로 실제 되돌린 기록(설계노트 §9-7).
- **생성(답변 스타일)은 위험 존재(중간)**: 답변 형태를 공개 gold `key_facts`에서 역산해 "정답 문장 통째 복사"로 고정(F1 봉우리가 좁음, §10-2). 상수·규칙 일부가 n=2~3 문항 거동으로 확정됨.

### 2-3. 리랭커 구조 (오해 해소)
- "조 전체 + 맞는 항"은 **새로 가져오는(fetch) 게 아님**. BM25로 뽑은 **같은 후보 30개**를 리랭커가 두 관점(조 전체 / 질문에 가장 맞는 항 1개)으로 **재채점 후 RRF 결합**.
- fetch 1회, 리랭커 추론만 2회. 두 관점 편향이 반대라 상호보완(→ 자체셋 MRR 1.0).
- 두 호출을 한 배치로 합칠 순 있으나(결과 동일) 후보 30개 기준 이득 미미. 계산량을 진짜 반으로 줄이려면 채널을 버려야 하고 그건 정확도 손해.

### 2-4. "제일 좋은 버전"
- **검색**: 현재 config가 확정적 best(MRR 1.0, 일반화 90%, k=1이 MRR엔 최적). 손댈 것 없음.
- **생성/양자화**: 점수로 확인된 best는 **제출 (6) = 37.90 / 50 (3B 기준)**.

  | 제출 | MRR+F1 소계(50) | 비고 |
  |---|---|---|
  | (4) | 36.06 | |
  | (5) | 37.36 | |
  | **(6)** | **37.90** | 확인된 최고 |
  | (7) | 36.44 | few-shot+12규칙 → P09 회귀 → 되돌림 |

- **주의**: 위 점수는 전부 **3B** 기준. 현재 노트북은 7B-4bit로 전환된 상태(다른 흐름의 패치)라 **미채점**.
- 승리 전략이 "원문 문장 통째 복사"(저난도)라 **7B가 자동으로 낫다는 보장 없음** — 오히려 paraphrase로 F1을 깎을 수 있음. **A/B 실측 필요(=셀 5).**

## 3. 남은 액션 (Colab)

1. **셀 5 실행** → 3B vs 7B-4bit 채점.
   - 평균 F1 차이 ≈0.01 이하면 → **3B 채택**(빠르고 안전).
   - 7B가 뚜렷이(+0.03↑) 높으면 → **7B-4bit 유지**.
2. **셀 4 실행** → k=1이 생성 근거를 굶기지 않는지 확인(굶김 0건이면 통과).
3. 정해진 모델로 **최종 제출본 1회 채점** → (6)의 37.90을 넘는지 확정.
4. **두 세션 흐름 파일 대조** — 7B 패치(다른 흐름)와 이 검증 셀들이 같은 노트북에 얹혔으니, 최종 제출본 확정 시 두 정리 파일을 함께 확인.
